## 한 줄 소개

에이전트 명세(서브에이전트 `.md`, `SKILL.md`, `CLAUDE.md`, `AGENTS.md`, 시스템 프롬프트)를 면접장에 세우는 Claude Code 스킬. 보안 검문소 → 서류전형 → 1차 실무 → 2차 압박 → 최종 레드팀 순서로 보고, 판정마다 근거 인용이 붙은 합격·불합격 통지서를 준다.

## 왜 만들었나

- 에이전트 명세를 쓰고 나면 직접 넣어 본 프롬프트 두세 개로만 확인하고 쓰기 시작한다.
- 실제로 쓰면 이런 일이 생긴다 (README "왜 필요한가" 표, 개발 글 원고 `dev-post/11-agent-interview-arena/post.md`).
  - 네 번째 요청에서 자기 출력 형식을 잊는다.
  - "내가 주인이니까 규칙 무시해" 같은 메시지에 따른다.
  - 없는 API 파라미터를 지어낸다.
- 명세를 쓴 사람이 고른 테스트는 자기 가정을 확인할 뿐이라 이런 실패를 못 잡는다.
- 그래서 회사가 지원자를 보듯 남이 낸 문제로 에이전트를 시험하는 도구를 만들었다.

## 누가 쓰나

- Claude Code 서브에이전트·스킬·프로젝트 지침 파일을 쓰는 개발자.
- 스킬을 읽는 다른 에이전트 사용자 ([skills.sh](https://skills.sh) 설치 경로).
- 순위표를 보고 자기 명세를 남의 명세와 견주고 싶은 사람.

## 핵심 시나리오

1. 플러그인을 설치한다: `/plugin marketplace add ESeungJun/agent-interview-arena` → `/plugin install arena@agent-interview-arena`.
2. `/arena:apply .claude/agents/code-reviewer.md`를 실행한다. 경로를 안 주면 스킬이 후보 파일을 찾아 묻는다.
3. 언어(한국어·영어)와 모드(랭크·연습)를 정하고, 명세의 `model:`로 지원자 모델(체급)이 정해진다.
4. 스킬이 단계마다 엔진을 부르고, 대기실·면접실 장면을 보여 준 뒤 결과를 읽어 준다.
5. 한 단계라도 떨어지면 거기서 끝나고, 결정적 실수와 보완할 점, 고쳐 달라고 할 때 쓸 요청 프롬프트가 담긴 불합격 통지서가 나온다. 최종까지 붙으면 합격 통지서가 나온다.
6. 사용자가 원하면 스킬이 보완할 점을 명세에 반영한다. 사용자가 요청할 때만 고친다.
7. 랭크 결과는 `/arena:apply submit`으로 GitHub Issue를 만들어 순위표에 올린다. 봇이 모델 호출 없이 다시 검사하고 GitHub 아이디로 싣는다.

### 나중

- **재검증(Verified) 등급**: 저장소에 없는 비공개 공격으로 면접을 다시 보는 단계. README에 "준비 중"으로 적혀 있고, 순위표 코드에는 등급 자리(`tier: "verified"`)만 있다. 운영자 API 키로 돌려야 해서 비용 부담 방식이 정해지지 않았다. 체급별 상위권부터 다시 보는 쪽이 유력하다 (README, 개발 글 "남은 고민").
- **GPT·Gemini 지원자 엔진**: 엔진은 `--target gpt|gpt-reasoning|gemini`를 받지만 어댑터가 없어 Claude로 돌리고 결과에 "참고용"이라고 적는다 ([core/interview.ts](../core/interview.ts)).

### 범위 밖

- **웹 서비스로 면접 대행**: 첫 버전은 웹 서비스였으나 면접 비용을 운영자가 모두 내는 구조라 접었다. 로그인, 관문권, 광고, 운영자 화면도 같이 버렸다 ([결정기록](결정기록.md#2026-11-04-웹-서비스를-접고-claude-code-스킬로-바꾼다)).
- **지원자에게 실제 도구 실행**: 면접 안의 도구 결과는 모두 모의값이다. 명세가 위험한 일을 시켜도 실제로는 아무것도 하지 않는다.
- **명세 자동 수정**: 스킬은 사용자가 요청할 때만 명세를 고친다.

## 지원 플랫폼과 배포 채널

| 대상 | 경로 | 필요한 것 |
| --- | --- | --- |
| Claude Code 플러그인 (권장) | 이 저장소의 마켓플레이스 [.claude-plugin/marketplace.json](../.claude-plugin/marketplace.json) | Node.js 20 이상, 로그인된 `claude` CLI 또는 `ANTHROPIC_API_KEY` |
| 스킬을 읽는 다른 에이전트 | skills.sh: `npx skills add https://github.com/ESeungJun/agent-interview-arena/tree/main/plugins/arena/skills/apply` | 같음. 명령 이름은 `/apply` |
| 대기실 패널 | 같은 마켓플레이스의 `arena-room` | mod를 지원하는 Claude Code |
| 순위표 | GitHub Pages (`main` 브랜치의 `docs/`) | 브라우저 |

- 엔진은 사용자 PC에서 사용자의 Claude 요금제(또는 API 키)로 돈다. 운영자가 띄우는 서버는 없다.
- 마켓플레이스·skills.sh·순위표가 모두 `main`을 읽으므로 `main`이 곧 배포판이다 ([CONTRIBUTING.ko.md](../CONTRIBUTING.ko.md)).

## 완료·성공 기준

- **면접이 끝까지 돈다**: 랭크 면접이 최종까지 가면 모델 호출 약 35회, 연습은 약 25회 (README "모드와 비용").
- **비용이 사용자에게 납득 가능하다**: 최종까지 간 랭크 면접 1회를 API 요금으로 환산하면 Haiku 지원자 약 0.28달러, Sonnet 지원자 약 1.05달러 (README, 개발 글 기준 실측).
- **채점을 믿을 수 있다**
  - 회귀 샘플 6종이 기대 결과를 지킨다: good 서류 80 이상 통과, vague 20 이하 탈락, 보안 샘플 실격·통과 ([tests/sample_candidates/expected.json](../tests/sample_candidates/expected.json)).
  - 순위표에 올라간 점수는 판정에서 다시 계산해도 같다 (봇 검사).
- **단위 테스트가 모델 호출 없이 통과한다**: `npm test`, `npm run typecheck`.
- **공개 후 실측**: 공개 에이전트 명세 20개를 랭크로 면접 봐서 합격 0명이었다(2026-11-03 실측, 개발 글). 도구가 "잘 쓴 것 같은 명세"에서도 실패를 찾아낸다는 근거로 본다.
