# 💳 관문권 결제 계획

서류전형과 하루 첫 1차는 무료로 두고, 그 다음 관문(2차·최종, 무료 횟수를 넘긴 1차)은 관문권으로 연다 (D-48).
관문권 장부와 사용 규칙은 구현했다. 결제는 아직 붙이지 않았고, 그때까지는 운영자가 `/admin` 유저 탭에서 지급한다.

## 1. 원가와 가격

운영 첫 기록(2026-10-25, 경량급)으로 잰 단계별 원가다. 비용의 95% 이상이 면접관(Sonnet)이다.
D-47(갈린 항목만 세 번째 면접관)로 1·2차 면접관 비용이 줄어드는 만큼 아래 값보다 낮아진다. 운영자 화면의 단계별 평균 비용으로 다시 잰다.

| 관문 | 원가 (D-47 전) | 받는 것 |
|---|---|---|
| 서류전형 | $0.16 | 무료 (체급별 하루 3장) |
| 1차 | $0.47 | 계정당 하루 1번 무료, 넘으면 관문권 |
| 2차 | ~$0.47 (1차와 비슷하다고 가정) | 관문권 |
| 최종 | ~$0.47 (같은 가정) | 관문권 |

- **관문권 1장 990원.** 부가세·결제 수수료(약 3.5%)를 빼면 약 865원(환율 1,400원 기준 약 $0.62)이 남아 관문 하나 원가를 덮는다.
- **체급별 장수**: 경량·중량 1장, 무제한(지원자 Opus) 2장. 지원자 엔진 원가가 단계당 경량 약 $0.01, 중량 약 $0.15, 무제한 약 $0.3 이다.
- **BYOK 는 껐다.** 처음 보는 사이트에 API 키를 넣는 사람이 드물다. 무제한급도 운영자 키로 돌리고 관문권으로 받는다. 키 처리 코드는 남겨 두고 체급 설정(`byok`)으로만 끈다.
- 가격은 시즌 데이터로 평균 원가가 나오면 다시 본다. 모델 가격과 환율은 결제를 열기 전에 다시 확인한다.

## 2. 사용 규칙 (구현됨)
- 서류전형: 새 .md 를 낼 때 서류 티켓 1장 (`tickets.challenge = 'doc'`). 같은 분기 같은 .md 재제출은 쓰지 않는다.
- 1차: 계정당 하루 `ARENA_FREE_R1`(기본 1)번은 무료 티켓(`tickets.challenge = 'r1'`), 넘으면 관문권.
- 2차·최종: 관문권 (`pass_ledger` 에 `use` 로 뺀다).
- 서버 오류 뒤 다시 시도(3번까지)는 이미 낸 관문이라 더 쓰지 않는다.
- 접수에 실패하면(동시 상한, 대기열 꽉 참) 무료 티켓은 지우고 관문권은 `refund` 로 돌려준다.
- 관문권이 모자라면 402 와 함께 "결제는 준비 중" 안내를 낸다. 면접장 화면도 버튼을 막고 같은 안내를 보인다.

## 2-1. 상점 화면 `/shop` (구현됨)
- 바탕화면 아이콘과, 관문권이 모자란 면접장 화면에서 들어온다.
- 상품(관문권 990원), 수량(1·3·5·10장, 최대 20장), 결제 수단(카드·토스페이·카카오페이·네이버페이), 주문 요약(공급가액·부가세), 이용 안내·환불 규정 동의, 보유 장수와 증감 내역을 보여 준다.
- 결제를 열기 전에는 결제 버튼을 "결제 준비 중"으로 막아 둔다 (`app/shop/Shop.tsx` 의 `PAYMENTS_OPEN`). 결제를 붙일 때 이 버튼이 4번 흐름의 주문 생성을 부른다.
- 남은 관문권은 시즌이 바뀌어도 그대로 쓴다.

## 3. 데이터

| 표 | 내용 |
|---|---|
| `tickets` | 무료 티켓. `challenge` 로 서류(`doc`)·무료 1차(`r1`)를 가른다 |
| `pass_ledger` | 관문권 증감(`grant` 운영자 지급, `purchase` 결제, `use` 사용, `refund` 돌려줌). 잔액은 계정별 `delta` 합계 |
| `orders` (결제 때 추가) | 주문 id, 계정, 장수, 금액, 통화, 상태(대기·결제됨·취소·환불), 결제 대행사 결제 키, 만든 시각 |

모든 표에 RLS 를 켜고 정책은 두지 않는다 (지금 표와 같음).

## 4. 결제 흐름 (구현 전)
1. 화면에서 장수를 고르면 서버가 주문(`대기`)을 만들고 금액을 서버가 정한다. 화면이 보낸 금액은 믿지 않는다.
2. 결제창(대행사 SDK)에서 결제한다. 국내 사용자 위주라 토스페이먼츠를 우선 본다.
3. 대행사가 결제 결과를 서버로 알린다(웹훅). 서버는 서명을 검증하고, 대행사 API 로 결제 금액·상태를 다시 조회해 주문 금액과 맞춘다.
4. 맞으면 한 트랜잭션에서 주문을 `결제됨`으로 바꾸고 `pass_ledger` 에 `purchase` 를 더한다. 같은 웹훅이 여러 번 와도 주문 id 기준으로 한 번만 반영한다.
5. 화면은 주문 상태를 조회해 결과를 보여 준다.

## 5. 환불
- 쓰지 않은 관문권만 환불한다.
- 전자상거래법상 청약 철회(구매 후 7일)를 안내하고, 쓴 관문권은 철회 대상에서 뺀다는 것을 결제 전에 알린다.
- 서버 오류로 면접을 마치지 못한 관문은 다시 시도할 수 있으므로 환불 대상이 아니다.

## 6. 열기 전에 필요한 것 (코드 밖)
- 사업자 등록, 통신판매업 신고, 대행사 가맹 심사
- 이용약관·환불 규정·개인정보 처리방침(결제 정보는 대행사가 보관, 우리는 주문·결제 키만)
- 세금계산서·현금영수증 처리 방식

## 7. 광고 (보조)
보상형 광고 1회 수익(대략 1~3센트)으로는 1차 이상 관문 원가를 덮지 못한다. 쓴다면 서류 티켓을 늘려 주는 용도로만 쓴다.

## 대안 (선택하지 않음)
- 원가 기준 묶음 티켓(1장 4,900원 등): 최악(최종까지 합격)을 기준으로 잡아 너무 비쌌다.
- 서류~1차 전부 무료: 무료 한 판이 운영자에게 약 $0.6 이다. 1차는 하루 1번만 무료로 묶었다.
